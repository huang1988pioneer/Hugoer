# 桌面版導覽重構：把「步驟」當成預算

Hugoer 桌面版原本是七個並列分頁（環境／設定檔／主題／文章／遷移／選單／Git 部署）。
分頁本身沒有錯，錯的是**它把「Hugo 的概念」當成介面骨架**，於是使用者必須先學會
七個名詞，才知道自己現在該點哪一個。這份文件說明改成什麼、以及為什麼。

## 設計原則

1. **任何時刻只有一個主要動作。** 首頁正中央永遠只有一顆大按鈕，內容依現況變化。
2. **高頻動作全域可達。** 「新增文章」與「發布」放在頂列與快捷鍵，不依賴目前在哪一頁。
3. **進階功能不刪除、只降級。** 七個分頁一個都沒少，只是把低頻的五個收進「更多」。
4. **合併必然連續的步驟。** 例如安裝主題後一定要啟用，就由同一顆按鈕做完。
5. **鍵盤是最短路徑。** Ctrl+K 命令面板讓任何功能都是「一次輸入 + Enter」。

## 骨架

```
┌──────────────────────────────────────────────────────────────────────┐
│ Hugoer  [網站名]      [🔍 搜尋功能或動作…  Ctrl+K]   ＋新文章  ▲發布  │
├──────────────────────────────────────────────────────────────────────┤
│ ◆首頁  ✎文章  ▲發布        更多 ▾              (狀態訊息)            │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  目前頁面                                                            │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

- **主要區（永遠可見）**：首頁、文章、發布。
- **更多 ▾**：環境、設定檔、主題、選單、遷移，各附一行說明；程式碼統計移到此選單底部。
- **命令面板**：Ctrl+K 開啟，↑↓ 選擇、Enter 執行、Esc 或點暗色區關閉。

## 首頁＝狀態機

首頁不是儀表板堆疊，而是一台狀態機。它依序檢查五件事，第一個沒完成的就是「下一步」：

| # | 判斷           | 主要按鈕              | 取代的原本路徑                                   |
|---|----------------|-----------------------|--------------------------------------------------|
| 1 | Hugo 是否安裝  | 一鍵安裝 Hugo Extended | 環境 → 捲動 → 安裝                                |
| 2 | 是否有網站     | 建立網站（附目標路徑） | 環境 → 捲動 → 填父資料夾 → 填名稱 → 建立          |
| 3 | 是否有主題     | 安裝並啟用 Stack 主題  | 主題 → 安裝 → 回清單選取 → 啟用                   |
| 4 | 是否有文章     | 新增文章              | 文章 → 填標題 → 新增                              |
| 5 | 是否有線上網址 | 前往發布              | Git 部署 → 找到推送按鈕                           |
| — | 都完成         | 新增文章（日常模式）  | —                                                |

五站進度列同時顯示 `✓ 已完成 / ▶ 進行中 / ○ 待完成`，狀態不靠顏色單獨表達。
下方是「最近文章」（點一下直接進編輯器）與「網站現況／快捷動作」兩張卡。

## 步驟數對照

| 任務                   | 原本 | 現在 |
|------------------------|------|------|
| 首次啟動 → 網站可預覽  | 9–12 | 3（安裝 → 建立 → 套主題，各一顆按鈕） |
| 新增一篇文章           | 3    | 1（Ctrl+N 或頂列按鈕，任何頁面皆可） |
| 從編輯中跳到發布       | 2    | 1（Ctrl+Shift+P 或頂列按鈕） |
| 打開本機預覽           | 3    | 1（Ctrl+P：沒開就開、開了就跳瀏覽器） |
| 進入任一進階頁         | 1    | 1（更多 ▾）或 Ctrl+K 直接搜尋 |

## 快捷鍵

| 快捷鍵        | 動作                         |
|---------------|------------------------------|
| `Ctrl+K`      | 命令面板                     |
| `Ctrl+1/2/3`  | 首頁／文章／發布             |
| `Ctrl+N`      | 新增文章並進入編輯器         |
| `Ctrl+S`      | 儲存目前文章                 |
| `Ctrl+P`      | 本機預覽（自動開瀏覽器）     |
| `Ctrl+Shift+P`| 前往發布                     |

## 實作位置

| 檔案                             | 角色                                             |
|----------------------------------|--------------------------------------------------|
| `ViewModels/ShellContracts.cs`   | 頁面代號、`IShellNavigator`、命令面板項目模型     |
| `ViewModels/HomeViewModel.cs`    | 首頁狀態機、進度列、聚合動作                      |
| `ViewModels/MainViewModel.cs`    | 主／進階導覽分組、全域命令、命令面板              |
| `Views/HomeView.axaml`           | 英雄卡、五站進度、最近文章、快捷動作              |
| `Views/MainWindow.axaml(.cs)`    | 外框、快捷鍵、Ctrl+K 面板                         |
| `App.axaml`                      | `hero` / `navSeg` / `quickAction` / `palette*` 樣式 |

## 沒有改變的事

- 七個原有頁面的內容與 ViewModel 行為完全未動。
- 發布仍需使用者在發布頁明確確認，首頁不會替使用者推送。
- 深色主題色票（graphite / cyan）沿用；橘色只保留給「發布」這個決策動作。
