# Hugoer v1.3.0

Hugoer v1.3.0 adds deployment-version monitoring for GitHub Pages.

## Highlights

- Generate a unique `static/hugoer-deployment.json` marker for every create, connect, and push deployment.
- Check the live marker every five minutes with cache bypassing enabled.
- Distinguish four honest states: waiting for the first marker, previous version, latest version, and temporarily unavailable.
- Notify the user in the GitHub page and the global application status bar when the live site reaches the latest deployment.
- Provide an **立即檢查線上版本** action without interrupting the five-minute background schedule.
- Handle missing markers, mismatched versions, HTTP failures, malformed responses, offline connections, and timeouts.
- Stop the background monitor cleanly when Hugoer exits.

## How it works

After a deployment, Hugo copies the marker from `static/` to the published site root. Hugoer requests the live marker with no-cache headers and a cache-busting query, then compares its deployment ID with the local expected ID. A normal HTTP 200 alone is not treated as proof that the latest website is online.

## Verification

- Latest marker, previous marker, and missing marker integration scenarios pass.
- Deployment monitor and GitHub Pages permission regression checks pass.
- Release build completes with zero warnings and zero errors.

## Notes

- An existing site starts version monitoring after the first deployment made with Hugoer v1.3.0.
- Windows artifacts are not code-signed, so Windows SmartScreen may show an unknown publisher warning.
